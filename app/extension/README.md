# フリマコピー（自作）v0.10.9

跨平台复制出品用的自作 Chrome 扩展（Manifest V3）。
来源侧在商品页一键读取出品信息并暂存；v0.2.0 起，出品侧可在目标平台的出品页一键自动填充。

- 不连接任何远程服务器、无统计、无外部依赖
- 仅使用本地存储、闹钟、脚本注入权限（外加读取页面所需的 host_permissions）
- 数据只保存在本机 `chrome.storage.local`（键名 `copyData`）

## 安装方法

1. Chrome 打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本文件夹（`furima-copy-extension/`）
4. 工具栏会出现扩展图标（默认图标）

## v0 已实现

- 对应 4 个平台的商品页，右下角会出现红色悬浮按钮「📋 この商品をコピー」：
  - Mercari：`https://jp.mercari.com/item/*`
  - ラクマ：`https://item.fril.jp/*`、`https://fril.jp/item/*`
  - PayPayフリマ：`https://paypayfleamarket.yahoo.co.jp/item/*`
  - Yahoo!オークション：`https://auctions.yahoo.co.jp/jp/auction/*`
- 点击后提取并保存以下信息（取不到的项目为 null / 空，不会报错中断）：
  - 标题、商品说明、价格（数值）、图片 URL 列表、出处平台、出处 URL
  - 商品状态、分类、运费相关文字（页面上有规格表时）
- 提取方式（多重兜底）：
  - Mercari：优先解析页面内嵌的 `__NEXT_DATA__` JSON（递归找商品对象），失败再读 DOM
  - 其他三家：优先 JSON-LD（Product），再读 DOM，最后用 `og:title` / `og:image` 兜底
  - 图片 URL 会去掉明显的缩略图尺寸参数，尽量拿较大图，并去重
- 成功后页面上会弹出提示「コピーしました：<标题>（画像N枚）」
- 点工具栏图标打开弹窗：可看到当前暂存的商品（平台、标题、价格、首图、图片数、复制时间），并可「クリア」清除
- 按钮注入是 SPA 安全的：页面内跳转导致按钮消失时会自动恢复，不会重复出现两个

## v0.2.0 新增：出品页自动填充

**使用流程**

1. 在来源平台的商品页点「📋 この商品をコピー」（暂存标题/说明/价格/图片等）
2. 打开目标平台的出品页，右下角会出现蓝色悬浮按钮「📥 コピー内容を入力」
3. 点它：能自动填的字段直接填入，填完后右上角弹出结果面板，逐项列出 ✅ 已填 / ✋ 需手动（附暂存的候选值）/ ⚠️ 失败
4. 人工核对面板里标「手動」的项目，确认无误后**自己**点出品

通常的复制、填充和远程任务不会点送信/出品按钮；Yahoo! 未落札商品的批量再出品是一个需要用户明确勾选并启动的例外。

## v0.10.9 修复 Yahoo! 再出品按钮识别并保留全分页与 Todo 扫描设置

- 预览会逐页读取所有未落札商品，不会处理「落札者あり」。必须勾选确认后再次点击开始；最多处理 1000 件。

- 每件商品依次通过「再出品」页面和 `/sell/jp/show/preview` 确认页面，最后自动提交。扩展只点击页面内唯一且文本匹配的操作按钮。
- 页面出现无法识别的按钮、商品 ID 不一致或不能确认提交完成时立即停止，不继续下一件；失败页面会保留以便检查。
- 可从网页面板请求在当前商品处理结束后停止。处理进度保存在本地 `chrome.storage.local`。
- 弹窗的「Mercari Todo 扫描」可单独开关定时扫描，间隔可设为 1–1440 分钟或 1–24 小时；也可手动立即扫描。需配置管理程序地址/令牌并保持桌面管理程序运行。管理任务轮询与 Todo 扫描互不依赖。

**各平台自动 / 手动一览**

| 平台（出品页） | 自动填充 | 尝试自动（原生下拉文本匹配） | 手动（面板给出候选值） |
|---|---|---|---|
| Mercari `/sell/*` | 标题、说明、販売価格、图片 | － | カテゴリ、商品の状態、配送・送料 |
| ラクマ `/item/new` | 商品名、说明、価格、图片 | 商品の状態、配送料の負担 | カテゴリ |
| PayPayフリマ `/item/add` | 商品名、说明、価格、图片 | － | カテゴリ、商品の状態、配送・送料 |
| Yahoo!拍卖 `/sell/jp/show/submit` | タイトル、说明、開始価格、图片 | 商品の状態 | 希望落札価格、カテゴリ、配送・送料、その他 |

- Mercari / PayPayフリマ 是 React/Next 的 SPA，カテゴリ等是自制下拉组件，程序点击不可靠，所以只给候选值、由人工选
- 图片填充方式：background（service worker）代理下载图片（绕过内容脚本的 CORS 限制）→ 转成 File → 塞进页面的 `input[type=file]`；有 `multiple` 的输入框一次性全塞，单张输入框则逐个分配
- 文本填充用 React 兼容的 native setter + input/change 事件，SPA 表单也能识别

**测试方法（v0.2.0）**

1. 重新加载扩展（`chrome://extensions` 里点该扩展的刷新按钮，或移除后重新「加载已解压的扩展程序」）
2. 在平台 A 的商品页复制一件商品
3. 打开平台 B 的出品页，点「📥 コピー内容を入力」
4. 反馈时请带上：结果面板的截图或内容 + F12 Console 里 `[FurimaCopy]` 开头的日志（日志会写明每个字段是靠哪种方式找到的：selector / placeholder / label，图片每一步的结果）

## v0.5.0 新增：リモート指令（半自動・検証版）

在聊天里让助手下指令，PC 上的扩展自动把已售商品重新填好出品页，最后点「出品」的是本人。

**仕組み**

- 扩展的 service worker 每 1 分钟轮询弹窗里设定的「指令 URL」，取回 JSON：
  `{"id": "唯一ID", "type": "relist", "itemUrl": "https://jp.mercari.com/item/mXXXX"}`
- 只执行没执行过的 id。执行流程：商品页在后台标签打开 → 自动读取（含图片取り込み）→ 出品页在前台标签打开 → 自动填充 → 结果写入 `lastRemoteResult`，弹窗里能看到状态和结果
- 兼容两种指令 URL 形式：直接返回上面 JSON 的 URL；或 GitHub Gist API 形式（`https://api.github.com/gists/<id>`，取 `files.command.json` 的内容）
- **远程执行也绝不点出品按钮**；分类/成色/配送等手动项和本地填充时一样在结果面板里提示

**設定（ポップアップ下半分）**

1. 「リモート指令を受け付ける」にチェック
2. 指令 URL を入力して「設定を保存」
3. 「今すぐチェック」で即时轮询；「テスト実行」は指令 URL 不要で、输入した Mercari 商品 URL に対してその場で実行チェーンだけを検証できる

**v0.5.1 修正**：商品ページを裏タブで開くと Chrome のスロットリングで描画と画像の遅延読み込みが進まず読み取りが止まる（実測）ため、商品ページも前面で開くようにした。実行中はタブが 2 回切り替わる。

**検証版の制限**

- 対応は Mercari → Mercari の再出品のみ。他平台 URL はエラーになる
- PC が起きていて Chrome が開いていること、Mercari にログイン済みであることが前提。验证码/二次验证が出たら本人の操作が要る

## v0.6.0 新增：在庫台帳（統一在庫）

四平台合并成一份本地库存。数据存 `chrome.storage.local` 的 `inventoryV1`，不上服务器。

**開き方**：ポップアップの「在庫台帳を開く」。

**レコードと識別**
- 一条记录 = 一款实物：商品名、首图、数量、状态（在库/出品中/已售待发货/已发货/已完成）、进货价（可选）、进货渠道、存放位置、备注
- 每条记录有管理番号 `FC-0001` 起流水。出品说明末尾写一行「管理No：FC-XXXX」作为识别标记：复制时读到编号就自动绑回同一条记录；填充时若暂存数据带编号，自动把编号行补进说明末尾——编号跟着内容流到各平台
- 记录下面挂各平台出品（链接/价格/状态）。任一出品标「售出」→ 数量 −1；数量到 0 而其他平台还有出品中 → 台账标红提醒下架
- 售出记录里在进货价已知时显示粗利（成交价 − 进货价，未扣手续费/运费）

**记录怎么进来**
1. ポップアップ「この商品を在庫に登録」：把当前暂存的复制商品建为记录并采番
2. Mercari 商品页复制时，说明里有编号就自动绑定（其他平台的绑定走下面的导入）
3. 台账页「URL 一括取り込み」：把已在各平台上架的商品 URL 一行一个粘贴，后台逐个打开读取建记录；同时保存首图的感知哈希（dHash）
4. 台账页「＋ 新規レコード」手动新建（未上架的囤货）

**疑似同款合并**：图片哈希一致或标题一致的记录会被列为「疑似同款」，照片并排确认后选一条保留、填合并后数量，点合并。绝不自动合并。

**备份**：台账页可导出 CSV / JSON，JSON 可再导入。删扩展或换电脑前先导出。

**v0.6.0 的限制**：列表页一键导入未做（先用 URL 粘贴导入）；ラクマ/PayPay/Yahoo 的复制时自动绑定未接入（导入和编号读取是全平台的）；下架仍需在各平台手点，台账只提醒。

## v0.7.0 新增：同プラットフォーム複写でカテゴリと商品の状態も自動選択

- コピー元と出品先が同じプラットフォームのときだけ（分類体系が同一のため）、カテゴリと商品の状態の自動選択を試みる。跨平台时仍只提示候选值、手动选（分类体系不对齐，硬套会错）。
- Mercari：カテゴリと商品の状態の両方。PayPayフリマ：商品の状態のみ（カテゴリは次回）。ラクマ/Yahoo は元々ネイティブ select の状態選択を試行済み。
- やり方：カテゴリはピッカーを開いて、検索ボックスがあれば葉カテゴリ名で検索→結果をクリック、無ければパスを階層ごとに辿る。商品の状態はドロップダウンを開いて同文言の選択肢をクリック。どちらも選択できたか結果パネルに ✅/✋ で出る。失敗しても他の項目は通常通り入り、候補値がパネルに残るので手動で選べる。
- リモート再出品（Mercari→Mercari）でも同じく効く。
- 注意：Mercari のカテゴリはコピー元から葉カテゴリ名しか取れていない場合があり、その場合は検索経由の一致に依存する。実ページ未検証のため、初回は結果パネルで当たったか確認してほしい。

## v0.7.2 修正：Mercari の商品の状態は独立ページで選択

- 状態の選択肢文言は辞書で確定：新品、未使用 / 未使用に近い / 目立った傷や汚れなし / やや傷や汚れあり / 傷や汚れあり / 全体的に状態が悪い（読み取り側の ID マッピングと一致）。

## v0.7.3 修正：カテゴリ選択でファイルダイアログが開く誤クリックを防止

- 実測で判明した不具合：カテゴリ選択の際、ラベルの親要素を辿る処理がフォーム全体まで登ってしまい、最初のボタンである「画像を選択する」を押して OS のファイル選択ダイアログが開いた（画像添付自体は完了していた）。
- 対策：①フォーム上の専用ページへのリンク（`a[href*="/sell/categories"]` / `a[href*="/sell/conditions"]`）を直接クリックする方式を最優先に変更。②コンテナ内トリガーにも安全条件を追加——`input[type=file]` を含む要素と「画像／写真」を含む文言の要素は絶対に押さない。③`fieldContainer` の制御要素判定に `a[href]` を追加し、リンクだけのセクションで登り過ぎないようにした。
- あわせて読み取り側も修正：カテゴリのパンクズが区切りなしで連結されていた（例「生活家電・空調生活家電掃除機・クリーナー…」）ため、末端要素ごとにテキストを集めて「 > 」で連結し直す。フィル側の階層辿り・葉カテゴリ検索が機能するようになる。

## v0.7.4 修正：PayPayフリマで初回表示時にコピーボタンが出ない

- 原因は Mercari v0.4.1 と同じ SPA 問題：PayPayフリマも Next.js SPA で、サイト内リンクから商品ページへ遷移してもページ再読込が起きず、`/item/*` にだけマッチしていた読み取りスクリプトが注入されない。リロードすると通常ロードになるためボタンが出た。
- 対策：PayPay の読み取り・出品ともマッチをドメイン全体（両ホスト）に広げ、スクリプト側でパス判定する。読み取りは `/item/<id>`（ただし出品ページ `/item/add` を除く）でのみ、出品は `/item/add` でのみボタンを出す。

## v0.7.5 修正：PayPayフリマのカテゴリ実装と、商品の状態の誤判定を修正

- 実測：PayPay 出品で結果パネルは「商品の状態 ✅ 未使用」と出たのに、フォーム上は未選択のままだった。汎用 `selectCustomByLabel` の成功判定（ラベルと値を含む要素が存在するか）が甘く、隠れた選択肢リストなどに反応した誤判定。
- PayPay 専用の選択処理を新設：成功判定は「フォームの行（ラベル＋値ボックス）に実際に値が表示されたこと」だけに限定。カテゴリも同方式で新規実装（値ボックスを押す→ピッカーでパスを階層ごとにクリック→フォーム表示で検証）。同プラットフォーム複写（PayPay→PayPay）のときだけ試行する。
- Mercari 側の状態フォールバックも、汎用判定を鵜呑みにせずフォーム表示で再確認するよう統一。

## v0.7.6 新機能：商品ページでコピー先を選ぶと出品ページで自動入力

- 商品ページのコピーボタンにホバーすると「コピーして出品ページへ」メニューが出て、コピー先（メルカリ / ラクマ / PayPayフリマ / Yahoo!オークション）を選べる。普通にクリックすれば従来通りコピーだけ。
- 選んだ場合の流れ：対象の出品ページを新しいタブで先に開く（ポップアップブロック回避）→ この商品をコピー（画像取り込み含む）→ 完了を `autoFillRequest`（chrome.storage.local）に ready として記録 → 出品ページ側の filler がそれを検知し、フォームの出現を待って一度だけ自動入力する（3分以内・対象プラットフォーム一致の場合のみ。消費後は消去するのでリロードで再実行されない）。
- 最後の出品ボタンは従来通り絶対に押さない。結果は出品ページの結果パネルで確認できる。

## v0.7.7 修正：PayPayフリマのカテゴリがピッカーを開いたまま止まる

- 実測：カテゴリのピッカー（モーダル）は開くのに第一階層が選べず、開いたまま手動判定になっていた。原因は、コピー元のカテゴリパスが区切りなしで連結されていた（例「スマホ、タブレット、パソコンその他」）ため、セグメント完全一致の探索が第一階層「スマホ、タブレット、パソコン」に当たらなかったこと。
- 対策：前方一致の探索を追加。残りパス文字列の前方一致になる選択肢（最長一致優先）をクリックして消費しながら階層を辿るため、区切りあり／なし両方のパスに対応。失敗時はピッカーを閉じる（×ボタン→Escape）ようにし、開きっぱなしにしない。
- なお商品の状態は v0.7.5 の方式で実際に選択できることを同画面で確認済み。

## v0.7.8 修正：PayPayフリマのカテゴリ値ボックス探索にフォールバックとログを追加

- 前提の訂正：v0.7.7 で案内した「ピッカーは開いた」という観察は誤りで、開いていたピッカーはユーザー自身が構造確認のために手で開いたものだった（ユーザー指摘）。つまりその実行ではカテゴリの値ボックスに到達できていなかった可能性がある。
- 対策：値ボックス探索に文書順フォールバック（ラベルの後ろに現れる最初の「選択してください」ボックス）を追加し、セクション辿りが外れても開けるようにした。読み取り側（fieldValue）にも緩いフォールバックを追加。あわせてカテゴリ／状態の各ステップに `[FurimaCopy]` ログを入れ、次に失敗したらコンソールで停止箇所が特定できるようにした。

## v0.7.9 修正：PayPayフリマの実物ソースに基づくピッカー操作の作り直し

ユーザー提供の出品ページ実物ソースで判明した事実：
- カテゴリ／状態のピッカーは PC（`#sell-category-pc`）と SP の2変種が、閉じた状態では画面外（translateY）で常時 DOM に存在する。`isVisible` では画面外も「見える」扱いになる。
- カテゴリ名は `span[data-category-id]`、状態名は説明文付きブロック内の `<p>` に入っている。値ボックスの表示テキストも `<p>` で、ボックスは div の入れ子。
- 閉じるボタンはテキストなしの画像ボタン（`img[alt="閉じるボタン"]`）。

旧コードの不具合：①値ボックスは一番外側のラッパーをクリックしていたため、内側のハンドラにイベントが届かなかった可能性が高い。②状態の選択肢探索に `<p>` が含まれず、完全一致が存在しなかった。③画面外の変種まで候補に入っていた。

各平台的页面结构（DOM、内嵌 JSON 的字段名）随时可能变化，本扩展的选择器是按一般结构写的兜底逻辑，**没有在登录状态的真实页面上逐项验证过**。

如果某个平台提取失败或字段缺失，请这样反馈：

1. 在该商品页按 F12 打开开发者工具的 Console
2. 再点一次「📋 この商品をコピー」
3. 把以 `[FurimaCopy]` 开头输出的那条对象内容发给我

有了这条输出就能判断是 JSON 结构变了还是 DOM 选择器失效，再针对性修。

## v0.10.0 変更点：再出品タスク（参照コピー方式）
- 管理プログラムからのタスクに type="relist" が追加された。参照商品（出品中・売却済みの自商品）の itemUrl を受け取り、その商品ページを開いて通常のコピーで staging し、出品ページへ自動入力、タスク指定時は自動出品まで行う。タイトル・説明・価格・画像はすべて参照商品からコピーし、管理プログラムのローカル画像は使わない。
- コピー後の copyData には管理プログラムの商品番号が inventoryCode（管理No）として付き、managerTask の印も付く。
- 結果は従来どおりプログラムへ返され、新しい出品 URL が返るとプログラム側で商品の参照 URL が自動で上書きされる。
- 従来型（type なし、プログラムから商品データと画像を受け取る）タスクも引き続き実行できる。
- 拡張側の在庫台帳（v0.6.0 で追加した lib/inventory.js / inventory.html / ledger.js、ポップアップの「この商品を在庫に登録」「在庫台帳を開く」、URL 一括取り込み、コピー時の自動バインド）は削除した。在庫管理は出品管理プログラム側に一本化する。管理No の引き継ぎ自体は残り、管理プログラムのタスクが付けた商品番号を、Mercari filler 内のローカル処理で説明末尾へ引き継ぐ。

## v0.10.1 変更点：自動出品（送信ステップ）の強化
- 実測で「入力は完了するのに出品するが押されない」事象があったため、送信ステップを全面的に診断可能化・堅牢化した。
  - 全ステージをコンソールへ記録する（[FurimaCopy][auto-submit] 接頭辞）: イベント受信、入力レポートの内容、ガード判定、ボタン発見、クリック、完了待ち。
  - ボタン探索を強化: button / [role=button] / a / div / span からテキスト完全一致（空白除去後）を探し、button 系を優先しつつ最小面積の要素（＝ボタン本体）を選ぶ。従来は button 要素しか探していなかった。
  - クリック後に反応が無ければ 6 秒後に素の click() で 1 回だけ再試行。確認モーダルの「出品する」が出たらそれも押す。
  - 結果パネルに「自動出品」行を追加し、成功/失敗と理由を画面上でも確認できるようにした。
